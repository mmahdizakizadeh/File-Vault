# FileVault — Teacher Frontend

پنل فرانت‌اند استاد FileVault با رابط فارسی و چیدمان RTL. فایل‌های HTML، CSS و JavaScript جدا نگه داشته شده‌اند و دادهٔ نمونه یا ورود ساختگی در این نسخه وجود ندارد.

## ساختار

```text
FileVault-Teacher-Frontend/
├── login.html
├── index.html
├── README.md
├── css/
│   ├── login.css
│   └── dashboard.css
└── js/
    ├── login.js
    └── dashboard.js
```

## امکانات رابط کاربری

- داشبورد واکنش‌گرا با منوی موبایل.
- ساخت و ویرایش سری تمرین؛ در فهرست فقط سری‌های منتشرشده نمایش داده می‌شوند.
- انتخاب چند فایل با اعتبارسنجی سمت کاربر (حداکثر ۱۰ فایل و ۱۰ مگابایت برای هر فایل).
- تاریخ مهلت با ورودی شمسی و نمایش تاریخ‌های شمسی/فارسی در جدول‌ها.
- فهرست ارسال‌ها بدون وضعیت بررسی و بدون فهرست مستقل دانشجویان.
- رابط آمادهٔ اتصال به API؛ در صورت نبود سرویس، دادهٔ ساختگی نمایش داده نمی‌شود.

## اجرای فرانت‌اند

پوشه را در VS Code باز کنید و با Live Server اجرا کنید. برای استفادهٔ واقعی، این پنل باید از طریق سرور وبی که مسیرهای `/api` را ارائه می‌کند اجرا شود. بازکردن مستقیم فایل یا اجرای مستقل Live Server به‌تنهایی بک‌اند ایجاد نمی‌کند.

## قرارداد API مورد انتظار

- `GET /api/teacher/me` — اطلاعات حساب استاد و بررسی نشست معتبر.
- `POST /api/teacher/login` — ورود واقعی با اعتبارسنجی سمت سرور.
- `POST /api/teacher/logout` — خروج و پایان نشست.
- `GET /api/universities` — دانشگاه‌های مجاز.
- `GET /api/universities/:id/courses` — درس‌های دانشگاه انتخاب‌شده.
- `GET /api/teacher/exercise-series?status=published` — سری‌های منتشرشده.
- `POST /api/teacher/exercise-series` — ایجاد و انتشار سری همراه فایل‌ها به‌صورت `multipart/form-data`.
- `PATCH /api/teacher/exercise-series/:id` — ویرایش سری موجود.
- `GET /api/teacher/submissions` — ارسال‌های ثبت‌شده.

ساختار پاسخ‌های فهرست می‌تواند آرایهٔ مستقیم یا شیء دارای `items` باشد. در داده‌های تمرین، فیلدهای `id`, `title`, `description`, `universityId`, `courseId`, `deadline`, `status` انتظار می‌رود؛ وضعیت سری‌های این پنل باید `published` باشد.

## وضعیت و محدودیت مهم

این بسته **فرانت‌اند آمادهٔ اتصال** است، نه سامانهٔ عملیاتی مستقل. بک‌اند، دیتابیس، ورود امن، آپلود واقعی، ذخیره‌سازی خصوصی فایل‌ها و کنترل دسترسی هنوز باید پیاده‌سازی و آزمایش شوند. فرم ورود عمداً اعتبارنامهٔ دلخواه را قبول نمی‌کند تا ورود آزمایشی با ورود واقعی اشتباه گرفته نشود. اعتبارسنجی مرورگر جایگزین اعتبارسنجی سمت سرور نیست.
